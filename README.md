# QUOKKA餐車 — 功能總覽（修改後）

單一 `index.html`，可直接在手機瀏覽器（含 iPhone Safari）開啟執行，資料儲存在瀏覽器 IndexedDB。

---

## 本次修改內容

1. **移除「連結健康」（iOS HealthKit）功能**，改為「上傳健康截圖 → 瀏覽器本機 OCR 辨識 → 使用者確認 → 儲存」的流程。
2. **步數派遣頁與日誌頁整合**：日誌的「每日印章」月曆已併入步數派遣頁，只保留一個月曆；底部導覽從 5 個項目改為 4 個。
3. 其餘花園／料理／餐車／存檔系統維持原樣，未受影響。

## 二、花園／地區派遣

- 展示目前選擇的角色，可切換不同角色查看好感度。
- 選擇地區、派遣隊員與（可選的）料理，開始「倒數式」派遣。
- 派遣進行中會顯示進度條與剩餘時間，時間到可領取結果。
- 派遣結果可能觸發角色好感事件（含好感度滿檔的特殊回饋）或取得食材。
- 好感度系統：每位角色有獨立好感值，顯示愛心數。

---

## 三、料理系統

- 多條料理線，可同時烹煮不同料理；隨等級解鎖更多料理線（需消耗代幣升級）。
- 檢查材料是否足夠才能開始烹煮，烹煮需要時間，時間到才能收取。
- 「小幫手」機制：指派角色自動代烹，並有每日次數上限。
- 料理圖鑑：可查看已解鎖 / 未解鎖的料理與所需材料。
- 每日簽到：依連續簽到天數給予不同獎勵。
- 已完成料理會進入庫存，供餐車販賣使用。

---

## 四、餐車系統

- 最多 4 台餐車，可分別解鎖。
- 每台餐車有自己的場景（草地／森林／花園／池畔／夕陽／星空／雪地／楓葉／雲端／糖果樂園等）與季節限定外觀。
- 餐車本體、屋頂、窗戶、櫃台、招牌、輪胎皆可更換造型／顏色。
- 餐車攤位可佈置裝飾品：直接在畫面上拖曳調整位置、縮放、翻轉或刪除。
- 顧客會自動出現排隊購買，售出料理會有提示動畫；統一售價 💰30。
- 可為餐車指派店員（角色），編輯販賣列表、環境與招牌。

## 五、步數派遣（本次修改重點）

### 5.1 步數來源：健康截圖上傳 + OCR
- 點擊「📷 上傳健康截圖」，選擇 iPhone「健康」App 的步數截圖。
- 圖片會先在畫面上縮放（最大寬度 1200px）以加快辨識速度，**不會上傳到任何伺服器**。
- 使用 [Tesseract.js](https://github.com/naptha/tesseract.js)（透過 CDN 載入函式庫本身，OCR 運算在瀏覽器本機執行，語言採用 `eng+chi_tra`）辨識圖片中的文字。
- 辨識邏輯會尋找「步數」／「Steps」關鍵字附近的數字，並優先採用標示「今天」／「Today」的數值，避免誤取「昨天」的步數；數字中的逗號或空白分隔（如 `8,532`、`8 532`）都能正確解析成 `8532`。
- 同時嘗試從圖片文字辨識日期（如 `2026/09/26`），辨識不到則預設今天。

### 5.2 確認畫面（絕不自動存檔）
- OCR 完成後一律彈出確認視窗，顯示（可編輯的）日期與步數欄位。
- 若辨識結果不夠明確（例如找不到步數、或同時有多個候選數字），會顯示「⚠️ 無法確定步數，請確認辨識結果」提示，但仍讓使用者手動輸入／修正後儲存，**不會自動存入錯誤數字**。
- 提供「🔄 重新上傳」可重新選圖再次辨識。

### 5.3 儲存規則
- 每一天只保留「目前確認的最新步數」，不會把同一天多次上傳的數字相加。
- 若新步數 ≤ 目前已記錄的步數，會提示「目前已記錄 X 步，未更新」，不會覆蓋。
- 步數大於 20 萬會提示需再次確認是否正確；大於 100 萬則直接拒絕（視為異常數值）。

### 5.4 任務／事件系統
- 每累積 **1000 步**觸發一次派遣事件，獎勵機率如下（已移除角色事件）：
  - 70%：獲得 1 個食材（6 選 1）
  - 20%：獲得 2 個食材（各自獨立 6 選 1，可能重複同一種）
  - 10%：獲得 1 份料理（8 選 1），直接進入料理庫存，供餐車販賣
- 事件結果會顯示在「今日步數派遣」清單中。
- **累積方式為跨日計算**：今天沒走滿 1000 步的零頭步數不會歸零，會自動留到明天繼續累加，直到湊滿 1000 步才觸發下一次事件。系統另外用一組不分日期的總計（累積總步數／已觸發次數）判斷，因此漏傳、隔天才補傳也一樣會一次補發所有應得的事件，不會少發也不會多發。
- 每天已觸發過的里程碑會記錄下來，**不會重複觸發**；即使漏傳、隔天才上傳截圖，系統也會一次補發所有應得的事件，不會少發也不會多發。

### 5.5 月曆／印章（原「日誌」功能已整合於此）
- 月曆會標示今天，以及每個「有紀錄的日期」蓋上小印章圖示。
- 點擊有印章的日期可彈出當天步數與派遣次數的小視窗。
- 可切換上一個月／下一個月查看歷史紀錄。

### 5.6 隱私
- 頁面上方顯示提示：「🔒 健康截圖僅用於本機辨識，不會保存原始圖片」。
- 系統只保存日期、步數與事件紀錄，**不會保存截圖原始圖片本身**。

## 六、存檔管理

- 資料存於瀏覽器 **IndexedDB**（非 localStorage），支援日後擴充更多資料。
- 📤 匯出存檔：輸出成 JSON 檔，可用於備份或換裝置。
- 📥 匯入存檔：讀取先前匯出的 JSON 檔還原進度。
- 🔃 更新到最新版本：重新載入頁面最新版本，不會刪除既有存檔。

## 九、如果未來要換回 HealthKit（原生 App）

若之後改用 iOS 原生 HealthKit：
- 只需在「健康截圖 OCR 辨識」區塊旁，新增一個等效於原本 `requestNativeSteps()` 的入口函式，呼叫 Swift 端並在收到資料後直接呼叫 `applyStepReading({date, steps})` 即可（此函式完全未變動，仍是唯一的「寫入步數」入口）。
- OCR 相關函式（`triggerStepScreenshotUpload`、`handleStepScreenshotUpload`、`runStepScreenshotOCR` 等）可以保留作為「沒有 HealthKit 權限時的備援輸入方式」，兩者互不衝突。
